## 1. 问题与机会

### 1.1 问题陈述

中型财险在个人意外险理赔上已具备 OCR 与规则引擎，但：

1. 条款 PDF / 规则引擎 / 拒赔话术库不同步 → 错赔或不当拒赔，且举证困难；  
2. 材料补件多轮往返 → 触碰《保险法》第22条「一次性通知补正」义务与消保投诉；  
3. 拒赔说明缺少条款项级引用 → 触碰第24条「说明理由」；  
4. 「秒赔」舆论抬高预期，复杂「疾病 vs 意外」案仍靠人工，缺少可验收的 AI 门禁。

### 1.2 机会陈述

把「条款 → 验收契约 → 裁决草案 → 独立校验 → 分层人闸」做成可回归的门禁中继，先在一个险种切片上证明：一次交对率与可追溯拒赔可相对基线改进，且不转移持牌核赔责任。

### 1.3 一句话产品

**条款门禁式理赔裁决辅助：输出带引用的结构化草案与补件清单，校验失败不得出款就绪，对外拒赔与超权限给付必须人批。**

### 1.4 非目标（Won't）

| ID | 非目标 |
|----|--------|
| W-01 | 健康/医疗诊断或治疗方案生成 |
| W-02 | 无人最终拒赔且不可申诉 / 不可人工复核 |
| W-03 | 纯客服话术机器人作为本期交付 |
| W-04 | 本期核心 L3 自动出款（另立项；能力 unmet） |
| W-05 | 车险查勘定损主链、重疾诊断给付 |

## 4. 方案概述

```text
条款/批单/手册（版本+生效日+效力栈）
  → Router（OCR | Rules | RAG | Investigate | Human）
  → Orchestrator：契约断言
  → Worker：抽取 / 理算步骤 / 裁决草案 / L2 回写（串行写）
  → Validator：独立检索 + Golden 打分
  → 失败关闭 / fix；应闸类型 → 人闸令牌
  → 文书导出（补件/拒赔）；支付仍走核心既有流程（非 L3）
```

**自治等级标注：** 辅助起草草案 = 诚实标注为低-中自治；**禁止**宣传为全自动无人赔付。

## 7. 人闸权限默认表（P0）

> **试点默认值**（对标中型财险常见分级逻辑）。上线前必须替换为客户《核赔权限管理办法》现行档，并由 SH-02 签字。见 §14-A1。

### 7.1 决定类型 × 是否默认人闸

| 决定类型 | 默认人闸 | 说明 |
|----------|----------|------|
| 补件 | 否 | 可自动；清单须一次完整 |
| 通赔建议 | 按金额档 | 见 7.2 |
| 减赔 | 按金额档；争议上浮一档 | — |
| 拒赔草案 | **是** | 对外前必须人批 |
| 通融 | **是** | 不得引用为「条款通赔」 |
| 预赔 | **是** | — |
| 调查中（进入） | 自动冻决 | 解除冻决必须人闸 |
| 调查解除冻决 | **是** | 仅调查岗/授权核赔 |

### 7.2 金额档（人民币，单次案件建议赔付额）

| 档 | 金额区间（默认） | 通赔建议 | 减赔 | 备注 |
|----|------------------|----------|------|------|
| A | ≤ 10,000 | 双人机审后抽检；可直通草案 | 主管闸 | 抽检入 Golden |
| B | 10,001–50,000 | 作业中心主管闸 | 主管闸 | — |
| C | 50,001–200,000 | 省级核赔负责人闸 | 同左 | — |
| D | > 200,000 | 总公司授权闸 | 同左 | 可叠加再保知会（Could） |

### 7.3 场景上浮（默认）

诉讼/信访/媒体、健康敏感病历争议、首次大额出险、通融、拒赔 → **至少上浮一档**；已是 D 则保持 D 并双人令牌。

### 7.4 硬约束

- 无 `human_latch_token` → `payout_ready` 必须为 false。  
- 通融若带「主险条款通赔」伪 citation → Validator 失败关闭（金标含本用例）。

## 8. L2 状态与字段对照（P0）

> 左侧为门禁规范状态；右侧为现网理赔系统**常见**语义。客户 IT 须填「现网枚举码」列后冻结接口。见 §14-A2。

| 门禁状态 | 含义 | 现网语义（待映射） | L2 回写要点 |
|----------|------|-------------------|-------------|
| `MATERIALS_INTAKE` | 材料受理中 | 立案后待收单/影像 | 只读保单+影像元数据 |
| `PENDING_SUPPLEMENT` | 待补件 | 补件中/待客户补充 | `supplement_checklist[]` 一次完整 |
| `PRIMARY_REVIEW` | 初审中 | 审核中 | OCR 字段、材料断言结果 |
| `ADJUSTING` | 理算中 | 理算中 | 免赔/比例步骤 |
| `INVESTIGATING` | 调查中 | 调查中/协查 | `payout_ready=false` 冻决 |
| `HUMAN_LATCH` | 人闸队列 | 待核赔审批/待上级 | 草案+citation+validator 报告 |
| `PENDING_APPROVAL` | 待审批 | 待复核 | — |
| `PAYOUT_READY` | 出款就绪 | 同意给付/待支付（核心） | **仅人闸后**；不触发银企 |
| `REJECTED_TO_EDIT` | 驳回修改 | 退回经办 | fail report |
| `NOTIFIED` | 已通知 | 已发补件/拒赔通知 | 文书 ID、发送回执字段 |
| `CLOSED` | 已结案 | 已结案 | 结案意见；支付仍核心人工 |

**L1 只读字段（最低集）：** `case_id`, `policy_no`, `product_code`, `clause_version`, `endorsement_flags`, `loss_date`, `claim_amount_claimed`, `image_ids[]`。

**主数据对齐：** 保单号、险别/条款代码、批单版本、案件号不一致 → 禁止进入 `PAYOUT_READY`。

## 9. Golden 启动 SOP（P1）

### 9.1 Owner

| 角色 | 职责 |
|------|------|
| 金标 Owner（SH-02 指定） | 抽样框、通过标准、是否允许提直通 |
| 标注组 | 2–3 名资深核赔双人独立标注 |
| 裁决人 | 第三人处理分歧 |
| 周回归 Owner（内审或理赔质检） | 每周跑 80–100 件；发布 blocked_expand 标志 |
| IT | 脱敏抽样管道、回归任务调度 |

### 9.2 抽样框

- 来源：近 12 个月**已决**个人意外险（含意外医疗）脱敏案。  
- 规模：≥300（最低）；目标 400–500。  
- 分层占比：补件 20% / 通赔 20% / 减赔 15% / 除外 20% / 效力冲突 10% / 调查 10% / 拒赔引用 5%。  
- **强制包含：** 通融伪 citation 负例；批单覆盖主险；同缺项多轮补件负例。

### 9.3 标注 SOP

1. 双人独立给出：裁决类型、关键断言真值、应引用条款项、是否应人闸。  
2. 分歧 → 第三人；记录理由。  
3. **禁止**模型自标自测作为唯一金标。  
4. 人闸改正 / 生产逃逸 → **48h 内**入库并开 fix Mission。

### 9.4 门禁

| 门槛 | 标准 |
|------|------|
| 关键断言 | ≥95% |
| 拒赔/减赔 citation | 100% |
| 裁决类型 | ≥90%（边界人闸不算自动成功） |
| 未达标 | 不得提直通、不得扩险种 |

### 9.5 pass bar 变更权

仅金标 Owner + 内审联签可改；改后必须全量重跑并通知 SH-01。

|-------|------|--------|------|
| R-OCR | 影像需结构化 | 既有 OCR | 人工录入 |
| R-RULES | 免赔/比例/权限/黑名单等可字段化 | 规则引擎/SQL | fail-closed→人审 |
| R-RAG-CLAUSE | 责任/除外/效力/拒赔理由 | 版本化条款 RAG | 手册→调查/人闸 |
| R-INVEST | 风险超阈/验真失败/重复索赔等 | 调查中+冻决 | 强制人闸 |
| R-HUMAN | 拒赔/通融/预赔/超阈/校验失败/申诉 | 人闸 | 无 |

### 10.2 冲突仲裁（同案多路由）

优先级（高→低）：**R-HUMAN > R-INVEST > R-RULES（金额/权限）> R-RAG-CLAUSE > R-OCR**。

- OCR 与规则冲突 → 以规则断言为准，OCR 字段标记 `needs_human_confirm`。  
- 规则与条款 RAG 冲突 → **fail-closed**，进人闸（禁止静默采信一侧）。  
- 调查触发 → 立即冻决，取消自动通赔路径。

### 10.3 效力栈（引用消解）

1. 批单/批注 → 2. 特别约定 → 3. 附加险条款 → 4. 主险条款 → 5. 投保告知/核保结论（影响认定，不万能改写条款）→ 6. 内部手册（对内作业；对外拒赔仍优先报备条款）。

每条 citation：`doc_id`, `clause_item`, `doc_version`/`effective_date`, `authority_rank`, `overridden_by?`。

### 10.4 Chunk / retrieval_profile

| profile | 用途 | 规则 |
|---------|------|------|
| `clause_v_current` | 责任/除外默认 | 仅当前生效版本；按条款项/节切块；保留加粗免责上下文 |
| `endorsement_priority` | 批单冲突案 | 先检索批单/特约，再主险；强制写 `authority_rank` |
| `handbook_ops` | 材料清单 | 仅对内补件清单；**不得**单独作为对外拒赔唯一依据 |

禁止：无版本过滤的「全文最大相似」作为拒赔依据。

Ledger 必记：`route_id`, `retrieval_profile`, `tool_acl_scope`, `decision_type`, `validator_score`。
