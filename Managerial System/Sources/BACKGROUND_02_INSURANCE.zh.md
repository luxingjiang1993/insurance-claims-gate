## 1. 行业与业务背景（详细）

### 1.1 行业画像

| 维度 | 要点 |
|------|------|
| 主体 | 财险、寿险、健康险、车险、相互保险、保险科技承保服务商、第三方管理（TPA） |
| 主体差异 | **持牌保险公司**：最终赔付/承保责任在己，采购追问审计与人闸；**科技服务商/TPA**：交付准确率与对接能力，监管问责仍可能传导至持牌委托方；**相互保险**：编制更薄，更依赖外包规则与手册 |
| 两条主价值链 | **承保（Underwriting）**：核保、定价辅助、除外与等待期落地；**理赔（Claims）**：立案、材料、定损、赔付、拒赔与追偿 |
| 理赔作业链（常见） | 立案 → 查勘/调查 → 定损/责任认定 → 理算 → 复核 → 支付；另有预赔、通融、追偿支线 |
| 核保特有对象 | 体检/病历、既往症、投保告知、加费与除外批注、延期/拒保、再保送审阈值 |
| 核心对象 | 条款 PDF、投保告知、影像/发票/公估报告、规则引擎、核心业务系统、支付出款 |
| 监管与专业约束 | 偿付能力、消费者保护、条款报备、理赔时效与可解释拒赔；错赔/惜赔均有成本 |
| 组织现实 | 精算与产品定条款、核保/理赔按手册执行、IT 维护规则与影像 OCR；手册更新常慢于案件压力 |

### 1.2 业务痛点（为何适合「条款门禁 + Agent 中继」）

1. **条款与系统规则不一致：** 纸质/PDF 条款已改，规则引擎或人工清单未改 → 错赔或不当拒赔。  
2. **材料与规则多跳推理：** 单次检索不够，需要「材料是否齐全 × 除外责任 × 免赔」组合判断。  
3. **拒赔/减赔不可追溯：** 客户投诉与监管问询时，说不清依据哪一款哪一版。  
4. **自动出款诱惑大、风险更大：** 无独立校验 + 无人闸的「自动赔」是事故温床。  
5. **纯对话 Agent 的陷阱：** 能聊天不能证明「所有必检断言已过」；理赔要的是 **可验收的裁决质量**。  
6. **欺诈与调查缺口：** 重复索赔、虚假发票、事故真实性存疑时，若无「调查中」闸与升级路径，自动化会放大损失。  
7. **效力冲突未建模：** 主险、附加险、特别约定、批单同时存在时，只检索「条款全文」仍会裁错。

### 1.3 理想业务闭环（架构映射）

```text
条款/批单/核保手册/理赔指引更新（带版本与生效日）
  → Orchestrator：RAG → 验收契约（材料齐全性、免赔、除外、等待期、效力冲突等断言）
  → Worker：实现抽取/规则校验/裁决草案或系统改动（串行写；默认不直连出款）
  → Validator：独立检索条款 + 黑盒/抽样案件集打分
  → 失败关闭 fix；对外决定与出款按「人闸分层」硬闸
```

**试点建议：** 先锁定 **一个险种 + 一条薄切片**（例如「免赔额与必传材料清单」），再扩到全险种。  
**集成原则：** 先读写案件状态与补件清单，再谈出款；写核心/支付必须 ACL + 灰度 + 可回滚。

### 1.4 险种切片差异（模拟时必须锁一种）

| 险种切片 | 材料重心 | 裁决难点 | 适合薄试点 | 慎入 |
|----------|----------|----------|------------|------|
| 车险 | 现场/定损影像、维修清单、交强/商业险责任划分 | 定损金额、责任比例、修理厂合作价 | 必传材料 + 免赔断言 | 全自动定损出款 |
| 意外险 | 病历、费用票据、意外经过证明 | 意外认定、等待期、责任免除 | 材料齐全 + 除外命中引用 | 医疗必要性判断 |
| 健康/医疗险 | 病历、发票、检查报告、既往症材料 | 等待期、既往症、责任免除、比例赔付 | 条款门禁 + 补件清单 | 诊断/治疗方案建议 |
| 企财险 | 损失清单、公估报告、消防/运维记录 | 保险标的、除外、施救费、残值 | 材料门禁 + 条款引用 | 复杂公估金额终裁 |
| 责任险 | 索赔函、诉讼材料、第三方损失证明 | 责任触发、抗辩、抗辩费用 | 触发条件断言 + 人闸 | 无人对外拒赔函 |

**模拟约束：** 一次模拟只选上表一行作为主产品线；另一价值链（承保/理赔）最多作 Should。

### 1.5 裁决类型枚举（输出不得只有「通过/拒绝」）

| 裁决类型 | 含义 | 是否通常要人闸 | 契约侧要点 |
|----------|------|----------------|------------|
| 补件 | 材料不齐，列出必传项 | 否（可自动） | 清单完整、可追踪 |
| 通赔 | 责任成立且金额在权限内建议赔付 | 按金额档 | 引用 + 金额计算可复核 |
| 减赔 | 免赔/比例/部分责任导致减额 | 视金额与争议 | 减额公式与条款依据 |
| 拒赔 | 不在责任或除外成立 | **是（对外）** | 条款效力栈 + 可申诉入口 |
| 通融 | 非严格条款内协商赔付 | **是** | 权限、理由、不得伪装成条款通赔 |
| 调查中 | 欺诈/真实性存疑，暂停自动裁决 | **是（升级调查）** | 触发规则、冻结出款 |
| 预赔 | 部分先行支付 | **是** | 额度、后续冲销关系 |

Worker 产出应为 **结构化裁决草案**（类型 + 引用 + 断言结果），不是聊天结论。

### 1.6 人闸分层（替代单一「高额才审」）

人闸至少按三维组合，而非只看金额：

| 维度 | 示例规则（模拟可用，非真实保司制度） |
|------|--------------------------------------|
| 金额档 | 如：≤1 万可双人机审后抽检；1 万–5 万主管闸；≥5 万高级别闸；巨灾/累计另册 |
| 决定类型 | 拒赔、通融、预赔、调查结论 → 默认人闸；纯补件可自动 |
| 险种/场景 | 健康险敏感案件、诉讼关联、媒体投诉、首次大额出险 → 上浮一档 |

**硬约束：** 自动出款不得绕过人闸；Validator 失败必须失败关闭，不得降级为「先赔后补日志」。

### 1.7 条款效力栈（引用必须落到可冲突消解的层级）

检索与引用时，按效力从高到低消解冲突（模拟默认序，客户可改）：

1. **批单 / 批注**（对保单的有效变更）  
2. **特别约定**  
3. **附加险条款**（就其承保范围）  
4. **主险条款**  
5. **投保告知与核保结论**（影响责任认定与除外落地，但不是「改写条款」的万能挡箭牌）  
6. **公司理赔/核保手册**（对内作业标准；对外拒赔仍优先落到已报备条款与约定）

每条 citation 应带：**条款代码/名称、条款项、版本或生效日、效力层级、是否被批单覆盖**。  
只做「全文相似检索」而无效力栈，不足以支撑合规问询。

### 1.8 中国监管与消保检查清单（采购常问条目）

模拟填表时，`regulators_and_regimes` / `constraints.compliance` 建议覆盖下列条目级提示（不必展开法条全文）：

| 条目 | 客户会问什么 | 产品侧应对 |
|------|--------------|------------|
| 条款报备与销售一致性 | 裁决依据是否为报备有效版本 | 版本化 KB + 生效日过滤 |
| 理赔时效与进度可见 | 是否加速立案/补件/结案，而非拖慢 | SLA 指标进 Eval |
| 拒赔说明义务 | 能否向消费者说清理由与依据 | 对外话术与对内引用分离，但同源 |
| 消费者申诉/异议 | AI 拒赔后如何回到人工 | 禁止「不可申诉」；人闸与工单回流 |
| 个人信息 / 敏感个人信息 | 病历、身份证、银行卡如何最小化与脱敏 | PII 护栏；健康险尤甚 |
| 自动化决策告知 | 是否告知存在自动化辅助、可否要求人工复核 | 安全声明 + 人闸分层 |
| 模型与日志审计 | 出事能否回放「谁在何时依据何款」 | 校验报告、citation、操作日志 |
| 数据出境与本地部署 | 病例/保单是否出域 | 部署与工具 ACL 约束 |
| 持牌责任不转移 | AI 是否被宣传为替代核保/理赔责任人 | Demo 安全声明为 Must |

### 1.9 现有技术栈与集成边界

国内险企常见已有能力：**核心业务系统、理赔系统、影像/OCR、规则引擎、电票/发票验真、银企支付、文档库**。新产品应讲清增量，而不是重复建设 OCR。

| 集成层级 | 内容 | 难度 | 试点建议 |
|----------|------|------|----------|
| L1 读 | 拉案件、保单、影像元数据、条款版本 | 中 | Must |
| L2 写状态 | 回写补件清单、裁决草案、门禁状态、人闸队列 | 中高 | Must |
| L3 出款/承保生效 | 触发支付、签发批注、改保单责任 | 高 | Should/Could；默认可人工在核心补录 |

**主数据对齐要点：** 保单号、险别/条款代码、批单版本、案件号必须一致，否则 citation 无法落到可执行规则。  
**写权限约束：** Worker「系统改动」仅限授权工具；需灰度、双人复核（对人闸）、失败可回滚；禁止演示环境直连真实支付。  
**峰值与降级：** 巨灾、年末、车险高峰时，允许降级为「只出补件清单 + 排队人审」，不得静默自动通赔。

### 1.10 模拟用业务 KPI 量级（非真实保司机密）

下列区间仅供叙事与验收口径，**必须标注为模拟量级**：

| 指标 | 模拟量级（示例） | 产品叙事用法 |
|------|------------------|--------------|
| 首次材料齐全率 | 试点前 40%–60% → 试点后 +10～20pt | 材料断言价值 |
| 二次补件率 | 下降 15%–30% | 清单自动化 |

| 错赔/回退率 | 目标不劣于基线；Eval 集回归为门禁 | 独立校验 |
| 拒赔投诉可追溯率 | 抽检 100% 具备条款级引用 | citation |
| 人闸命中率 | 拒赔/通融/超限额 100% 人审 | 人闸分层 |
| 断言通过率（Golden 集） | 上线门槛自定，如 ≥95% 关键断言 | `VP-METRICS` |

## 2. 市场与 AI 相关情报（2025–2026 语境）

### 2.1 宏观信号（偏中国落地）

- 保险与银行同属 **Agent 生产落地关注度高** 的垂直；承保、理赔、合规文档是常见切入点。  
- 国内险企数字化主线仍是：**影像 OCR + 规则引擎 + 人机协同**；增量预算更愿打在「文档理解、条款一致性、补件与裁决辅助」，而非端到端无人赔付。  
- 采购话术已从「能不能聊」转为「能不能过内审」：审计日志、人闸、错误升级、与核心/影像对接工作量。  
- 消保与投诉治理压力下，**可解释拒赔与时效**比「自动化率」更容易成为立项理由。  
- 无治理的 agentic 项目易被叫停——与国际分析机构对 agent 治理的风险提示同构：要追问 **审计、人闸、错误升级路径**。

### 2.2 产品叙事参考（国际视角，可弱引用）

| 视角 | 启示（保险场景） |
|------|------------------|
| 垂直 Agent 共识 | 保险是典型深流程、高价值、可产品化垂直 |
| 专业服务垂直付费逻辑 | 愿为「领域准确 + 工作流贴合」付溢价；保险同构 |
| Eval 导向 | 需要案件级 Eval 集与断言通过率，而非 demo 一次说对 |
| 编排先后 | 先做可编排的裁决流水线，再谈多 Agent 网络 |
| RAG 质量 | 条款版本、生效日、chunk 与引用质量决定能不能上线 |
| 结果导向 | 补件清单、裁决草案、门禁状态，而非聊天记录 |

对国内合规/业务负责人：优先讲 **作业流与监管条目**，少用人名清单作主要说服。

### 2.3 代表产品/赛道（竞品语境）

| 类型 | 市场语境 | 与我方差异 |
|------|----------|------------|
| 理赔文档 Copilot | 各类 claims AI / 医疗账单助手 | 多为辅助阅读；我方强调 **契约断言 + 独立 Judge + 赔付闸** |
| 核保自动化 | 垂直 underwriting agent / 规则评分 | 偏规则/评分；我方可讲「政策→可测行为」工程化 |
| 规则引擎 + OCR 本土方案 | 多数险企已有或在建 | 我方吃「条款版本化 + 多跳断言 + 独立校验」增量，不重复造 OCR |
| 通用 CX Agent | Sierra / Decagon 等 | 强在客户对话；保险条款裁决不是其主叙事 |
| 企业搜索 | Glean 等 | 可作条款检索底座；不足以单独满足合规门禁 |

### 2.4 本垂直最热的 AI 能力组合

1. **多模态/文档解析**（发票、影像说明）+ **条款向量/混合检索**  
2. **Router：** 结构化字段（SQL/规则） vs 非结构化条款 RAG  
3. **Agent 中继：** 契约 → 实现/裁决 → 独立校验  
4. **PII/敏感健康信息护栏**（健康险尤甚）  
5. **赔付与拒赔对外动作的人闸（分层）**  
6. **Golden 案件集 Eval**（错赔/漏赔/效力冲突回归）  
7. **欺诈/调查触发与冻结出款**（规则 + 人工升级）

### 价值映射提示

- 条款引用 → `VP-RAG-CITE`  
- 契约化核保/理赔规则 → `VP-CONTRACT-FIRST`  
- 独立复核 → `VP-INDEP-JUDGE`  
- 赔付闸 → `VP-HUMAN-LATCH`  
- 与金融共用平台 → `VP-DOMAIN-SWAP`  
- 案件回归指标 → `VP-METRICS` / `VP-FAIL-CLOSED`

## 5. 面试 / Demo 叙事要点

- **一句话：** 把保险条款变成可执行验收契约，Agent 中继产出带引用的裁决/系统行为，赔付与对外拒赔按分层人闸审批。  
- **选边：** Demo 声明主垂直是 `claims` 或 `underwriting`，并锁定 **一个险种切片**，避免两者都做深。  
- **必秀：** 效力栈 citation、缺材料断言失败、至少两种裁决类型（如补件 + 拒赔草案）、Validator 独立检索、人闸 approve 标志。  
- **加分秀：** 「调查中」冻款、批单覆盖主险条款的冲突消解。  
- **安全声明：** 不替代持牌核保/理赔最终责任；系统是门禁与加速器；支持申诉回人工。

## 6. 模拟客户时的边界

- 优先虚构「单一产品线」（如意外险理赔或企财险核保），并写明公司类型：总公司/分公司/相互/科技服务商。  
- 健康险可做材料与条款门禁，**不要**做成诊断 Agent。  
- 金额、通过率、KPI 只用 **1.10 量级数据**，并标注模拟，避免冒充真实保司机密。  
- 不要把 L3 出款写成 Must；不要把「无人最终拒赔且不可申诉」写成 Must。  
- 通融必须人闸，且不得在引用上伪装成条款通赔。
