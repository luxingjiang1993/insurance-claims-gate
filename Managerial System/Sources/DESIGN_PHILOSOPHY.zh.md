# 设计哲学 — Policy-to-Feature Missions（Agent 原生）

> **中文版说明：** 本文件为 `Managerial System/Constitution/DESIGN_PHILOSOPHY.md` 的中文译本，供 Sources 存档与中文阅读；冲突时以英文原版为准。  
> **读者：** coding agents（以及指挥它们的人类）。  
> **用途：** 重构本仓库，或从零搭建 Missions 风格系统。  
> **标准：** 硅谷生产级门槛 — 正确性优于表演；脚手架命名诚实；沿清晰的自主度阶梯升级。

**谱系（冲突优先级）：**
1. **主源：** 工厂式 Missions（Orchestrator / Worker / Validator）+ 对本仓库既有的改进要求  
2. **次源：** Sabrina Ramonov 单人 agentic 运营（中继技能、共享 brief、分级门禁、发布前人审）  
3. **三级影响：** Karpathy（agentic 工程 / 可验证性）、Shopify River–Aquifer（脑≠手、多人复利）、Anthropic（并行规则）、Dex Horthy 12-Factor Agents（掌控循环 / 上下文工程）、Sidekick 式法官校准 — 见 §14  
4. 冲突时 → **(1) 优先**，其次 (2)。吞吐、并行扇出或 vibe 速度，不得压过串行写者、失败关闭门禁，或共享可变代码库上的人闸。

---

## 1. 一句话教义

**人类架构并保留理解；由少数专职 Agent 组成的中继执行窄任务；持久账本（契约、brief、RAG、handoff）承载记忆，而 harness/上下文保持可弃与精选；独立且可校准的法官把关质量；高风险副作用需要硬性人闸；只在可验证处自动化；吞吐从属于正确性。**

---

## 2. 不可谈判的不变量

Coding agents **必须**遵守。违反不是风格问题，而是设计缺陷。

| ID | 不变量 | 理由 |
|----|--------|------|
| I1 | **角色激励分离** | Orchestrator 规划；Worker 实现；Validator/Grader 只评判。同一 Agent 不得既创造又最终验收自己的工作。 |
| I2 | **正确性先于实现** | 验收契约（行为断言 + 引用）先于功能代码存在。验收不得从实现倒推。 |
| I3 | **持久账本 + 精选上下文** | 跨步真源存在于版本化工件（契约、特性、handoff、RAG、Mission Control）— 而非聊天记忆。只把**下一步决策所需密度**装进模型（handoff 是压缩）。优先持久事件/状态基底；将 agent harness/会话视为可替换。成功轨迹应**回写**技能/KB（多人复利），而非死在私有窗口。 |
| I4 | **写串行；并行按决策规则** | 共享可变工作区上至多一个 Writer（`owns_paths` + 锁）。**可并行：** 检索、研究、独立评审、互不争夺的工件。**不可并行：** 同一文件/schema、写依赖，或协调/token 税超过加速 — 退回单会话。真正并行写之前必须 worktree 隔离。 |
| I5 | **门禁失败关闭** | 测试失败、校验失败或评分失败 → 阻断推进。门禁失败时永不标为 `DONE`。 |
| I6 | **人类架构、人闸与理解** | 人类定规格、权衡、预算与品味。可外包起草/思考辅助 — **不可**外包系统理解或发布责任。高风险动作需要明确人审。加速是 **agentic 工程**（守住质量门槛），不是把漏洞 vibe 上线的编码。 |
| I7 | **诚实标注自主度** | 若某步是脚本/编排，在代码注释与 handoff 中如实说明。不假装 LLM 自主，不假装 git commit。 |
| I8 | **先窄成功定义** | 先交付一条薄垂直切片（如日限额 + 审计策略），再加角色、并行或领域。优先带**廉价客观验证**的切片。 |

## 3. 角色模型（中继队，非蜂群）

保持阵容 **小而锋利**（约 3 个核心角色 + 可选只读工具）。宁可 7 个清晰技能，也不要 100 个含糊技能。

### 3.1 核心角色（必需）

| 角色 | 工厂名 | Sabrina 类比 | 拥有 | 不得 |
|------|--------|--------------|------|------|
| Planner | Orchestrator | Content coach | 澄清目标；检索政策/品牌；产出 **验收契约** + 特性/里程碑列表；根据 validator 报告打开 **fix** 特性 | 实现产品代码；最终验收 |
| Builder | Worker | Post writer | 每特性新鲜上下文；先测后码；真实补丁 + 真实 VCS handoff；遵守 `owns_paths` | 最终合规/评分验收；在另一 writer 运行时持有写锁 |
| Judge | Validator | Post grader | 独立检索配置/模型；对照 **契约** 细审 + 黑盒检查；只发失败报告；追求 **与人类校准** 的判断 | 修补被测系统；「好心」削弱契约 |

### 3.2 可选专家（只读或互不冲突）

- **Hook/Pattern 库** / 政策条款查找 — 工具 Agent，不是同一批文件上的第二写者  
- **改写 / 扇出** — 仅当输出**不**争夺同一可变工件。**绝不**在无锁/worktree 时把多个 writer 扇进同一 git 分支。  
- **调度 / 发布 / 部署** — 执行 Agent，**必须在人审门禁之后**

### 3.3 软编排，硬账本（掌控循环）

- 行为策略（拆分 / 重试 / 升级）：提示词 / 技能（软）。  
- 控制流、工具执行、重试、暂停/恢复、审批：**确定性应用代码**（硬）。LLM 发出结构化意图；应用拥有 switch。  
- 软层可随更强模型改进；硬层不得依赖模型记忆。  
- 优先 **脑 ≠ 手**：规划/账本/harness 放在沙箱文件/shell 变更的爆炸半径之外。

## 4. 共享工件（记忆总线）

所有 Agent 通过版本化工件读写。上下文窗口可弃，并**刻意压缩**。

| 工件 | 内容 | 生产者 | 消费者 |
|------|------|--------|--------|
| **验收契约** | 行为断言、验收、`machine_check`、`policy_clause_id`、广播约束 | Orchestrator | Worker、Validator、人类 |
| **品牌 / 领域 brief**（Sabrina） | 语气、产品、受众、非目标 — FinTech 映射为 KB 中的 **政策 + 产品约束** | 人类 + Orchestrator | 所有角色 |
| **特性列表** | 里程碑、claims 断言、`owns_paths`、kind=`implement`\|`fix` | Orchestrator | Runner、Worker |
| **RAG 知识库** | 政策、API 文档、审计发现、runbook；**版本 + 生效日**；通过后的回写 | 人类 + 细审更新 | 所有角色（按角色检索配置） |
| **Handoff 记录** | 已做 / 未做、命令 + 退出码、引用、process_followed、blocked_for_human — 为下一步 **压缩** | 每一角色 | Runner、Mission Control、下一 Agent、人类 |
| **评分 / 校验报告** | 通过/失败（或分数）、备注、引用；可选人类抽检字段 | Validator/Grader | Orchestrator（开 fix）、人类 |
| **Mission Control 状态** | 阶段、角色、写锁、预算、事件日志、审批人闸 | Runner | 人类（异步监督） |

### 4.1 契约质量规则

- 断言描述 **可观察行为**，而非实现。  
- 每条断言引用 KB 条款 ID；引用含 `doc_id`、`chunk_id`、`doc_version`、`retrieved_by`、`retrieval_profile`。  
- Validator 用契约 + **独立**检索评判 — 不以 Worker 笔记为唯一证据。  
- 优先 **执行** `machine_check`（API/E2E/脚本），而非硬编码 `A-001` 开关。  
- 先在验证廉价且客观处自动化（**可验证性经济**）；低可验证性判断留给人类。

### 4.2 评分门禁（Sabrina + 可校准法官）

- 明确阈值（全部断言通过；或分数 ≥ 9/10）。  
- 循环：构建 → 评判 → 修复 → 评判，直到达标或 **预算耗尽 → 人类**。  
- 限制修订轮次（如 3–5）。正确性预算压过虚荣吞吐。  
- 长期：抽检法官与人类一致性；独立但未校准的法官仍可能系统性出错。

## 5. 控制流（规范循环）

```text
人类目标 / 政策变更
    → Orchestrator：RAG → 验收契约 + 特性（+ 广播约束）
    → for feature in 串行队列:
          获取写锁
          Worker：窄 RAG → 测试 → 实现 → 真实 commit → handoff
          释放写锁
    → Validator：独立 RAG + 细审 + 对照契约的黑盒
    → if 失败: Orchestrator 打开 fix 特性（Worker 不得自合并绕过）
    → if 通过: 版本化 KB/技能回写（复利）
    → if 高风险副作用: 人类批准 → Scheduler/Deployer
    → if 阻塞: 停给人类（无静默无限重试）
```

**并行决策树（I4）：**  
研究/检索/评审 → 可并行 →  
同一可变工件或写依赖 → 串行 / 单所有者 →  
协调或 token 税 > 加速 → 单会话。

## 6. 自主度阶梯（不得跳级）

实现本系统的 agents **必须**诚实优先地逐级推进：

| 级别 | 名称 | 允许行为 | 本仓库目标 |
|------|------|----------|------------|
| L0 | **编排（Choreography）** | 确定性脚本；固定契约；开关切换 | 历史 demo 基线 — 清晰标注 |
| L1 | **门禁骨架** | 真实测试失败关闭；真实 HTTP 黑盒 validator；无假 git；禁止未使用的 `goal` | **继续改动的最低门槛** |
| L2 | **Schema 约束 Agent** | LLM 输出经 JSON Schema 校验；契约/特性经解析，不信任原文 | 下一步 |
| L3 | **可打补丁的 Worker** | Worker 编辑 worktree；handoff 含真实 diff + commit hash | **当前仓库目标（fix 路径）** |
| L4 | **契约驱动 Judge** | 检查来自验收/`machine_check`；独立模型/提供商；通向人类校准 | 反偏见叙事所必需 |
| L5 | **生产人闸** | 预算、审批、工具 ACL、凭证代理、动作审计 | 面试 + 真实运维门槛 |

改代码时：**优先升一级，而非加新的角色表演。**

## 7. 工具哲学（Agent 原生产品）

- 优先 **稳定工具**（API、MCP、CLI）；工具是由确定性代码执行的结构化输出。  
- 鉴权、限流与文档必须机器可读。  
- 按角色最小权限；**脑/harness** 不应与沙箱变更共享爆炸半径。  
- 将暂停/恢复与「联系人类」作为一等工具结果。  
- Mission Control 监督里程碑，而非 token 流。

---

## 8. 模型专长（「Droid whispering」）

- Orchestrator：最强推理 / 规划。  
- Worker：强编码，成本敏感。  
- Validator：指令严格、怀疑；**优先不同提供商或检索配置**。  
- 架构保持模型无关；换模型无需重写账本。

---

## 9. 本仓库的领域默认

**Policy-to-Feature（金融科技合规）** 仍为默认垂直：

- 共享 brief ≡ 政策 + API + 审计发现 KB。  
- Grader ≡ 对照 POL-XFER-* 引用的合规 Validator。  
- 发布人闸 ≡ 外部资金通道 / 生产 — demo 使用审批标志。

内容运营隐喻可启发 **评分量表形态**，但不得导致产品范围漂移，除非人类改换垂直。

---

## 10. 反模式（评审中拒绝）

1. 一个长跑 Agent 自己规划、编码并自我批准。  
2. 测试/校验失败时仍将特性标为 `DONE`。  
3. 假 commit、假「遵守 owns_paths」、未使用的 `goal` 参数。  
4. 为「速度」在同一分支上并行写。  
5. 把整库 KB / 原始日志塞进上下文，而非排序引用 + 压缩 handoff。  
6. Validator「就这一次」去改代码。  
7. 无限修订循环，无预算或人类升级。  
8. 仍停在自主度 L0，却声称生产多 Agent。  
9. 膨胀到几十个重叠 Agent/技能。  
10. 优化发帖量 / PR 数，却优先于契约通过率。  
11. 仅私有窗口的 Agent 胜利，从不回写 KB/技能。  
12. 为「更快」交付 vibe 编码带来的安全/正确性回退。

## 11. Coding agents 实现清单

合入变更前核对：

- [ ] I1–I8 仍成立（尤其精选上下文、并行规则、理解/人闸）  
- [ ] 新行为有工件或 schema，而非仅提示词文本  
- [ ] 应用拥有控制流；LLM 输出是结构化意图  
- [ ] Writer 路径失败关闭  
- [ ] Validator 不写产品代码  
- [ ] 高风险副作用由人类审批字段/API 门禁  
- [ ] Handoff 记录命令、引用、退出码（紧凑）  
- [ ] 若仍低于 L3，已文档化自主度  
- [ ] 无新的并行写路径，除非有锁 + `owns_paths`（真并行还需 worktree）  
- [ ] RAG 引用含版本 + 角色配置；通过时考虑 KB 回写  
- [ ] Mission Control / 状态 JSON 反映阶段、锁、门禁、审批

## 12. 成功指标（何谓「好」）

主指标（工厂权重）：

- 里程碑校验后的契约断言通过率  
- Fix 特性比例与校验轮次（预期 >1；按此设计）  
- Validator 抓住、Worker 测试漏掉的逃逸缺陷  
- 引用覆盖率（带有效条款版本的断言占比）  
- 验证成本相对挂钟时间（校验预算是预期，不是浪费）

次指标（Sabrina / 运营权重，不压过主指标）：

- 每里程碑 / 批次的人时  
- 到门禁时间；审批队列新鲜度  
- 回写率（更新 KB/技能的通过次数）  
- 抽检时法官–人类一致性

## 13. 可供引用的摘要（给 agents）

> 建 **中继**，不要建蜂巢。  
> **先契约后代码；验证你自动化的东西。**  
> **一个写者；多个读者；仅在廉价时并行。**  
> **持久账本；精选上下文；靠回写复利。**  
> **独立、可校准的法官；人闸与理解。**  
> **掌控循环；攀升阶梯；正确性复利。**

## 15. 已知缺口（尚未进入本哲学的实现门槛）

本文是 **工作教义**，不是完工的生产圣经。Coding agents **不得假装**下列已解决：

1. **Eval harness** — 尚无 missions 的 Ground-Truth / 回归套件；无系统的法官–人类 κ/一致性跟踪。  
2. **凭证代理与工具网关** — 已陈述最小权限；完整生产凭证隔离、网络策略与动作白名单尚未规定为可运行基底。  
3. **成本模型** — token、挂钟校验份额与协调税是指标目标，代码中未强制预算。  
4. **Worktree / 分支隔离** — 真并行写前必需；薄 demo 中非默认 runner 模式。  
5. **LLM 规划层** — Orchestrator/Worker 尚未成为 schema 约束的在线模型（阶梯 L2+）；此前编排须保持标注。  
6. **深度理解工具** — 人类「理解不可外包」缺少强制任务输入工件（架构笔记、威胁模型、ADR）。  
7. **知识回写自动化** — I3 要求复利；handoff→KB/技能的持久、经审提升仍薄。  
8. **组织/多人 UX** — Mission Control 偏单操作者；River 式可搜索共享会话语料暂不在范围。

补缺口时：自主度阶梯一次升一级；不要用角色表演掩盖缺失的基底。
