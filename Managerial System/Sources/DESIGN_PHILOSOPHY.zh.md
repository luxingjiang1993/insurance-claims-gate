## 1. 一句话教义

**人类架构并保留理解；由少数专职 Agent 组成的中继执行窄任务；持久账本（契约、brief、RAG、handoff）承载记忆，而 harness/上下文保持可弃与精选；独立且可校准的法官把关质量；高风险副作用需要硬性人闸；只在可验证处自动化；吞吐从属于正确性。**

## 2. 不可谈判的不变量

Coding agents **必须**遵守。违反不是风格问题，而是设计缺陷。

| ID | 不变量 | 理由 |
|----|--------|------|
| I1 | **角色激励分离** | Orchestrator 规划；Worker 实现；Validator/Grader 只评判。同一 Agent 不得既创造又最终验收自己的工作。 |
| I2 | **正确性先于实现** | 验收契约（行为断言 + 引用）先于功能代码存在。验收不得从实现倒推。 |
| I3 | **持久账本 + 精选上下文** | 跨步真源存在于版本化工件（契约、特性、handoff、RAG、Mission Control）— 而非聊天记忆。只把**下一步决策所需密度**装进模型（handoff 是压缩）。优先持久事件/状态基底；将 agent harness/会话视为可替换。**不为未使用的内容付税：** 优先懒加载 / 事件触发，而非 always-on 倾倒；每一段常驻字符串都在与工作空间抢位置。上下文税胜利**不能**替代 **verify-then-DONE**（I5）：门禁仍失败却更便宜，毫无价值。区分 **精选上下文工程**（版本化技能/KB/契约）与 **会话记忆**（模型自写草稿）— 后者不得自动晋升。成功轨迹应**回写**技能/KB（多人复利），而非死在私有窗口；**晋升需要显式评审人** — 机构 KB/技能默认 **人闸**；Validator 只能提议回写或给候选打分，不得静默合并进账本。 |
| I4 | **写串行；并行按决策规则** | 共享可变工作区上至多一个 Writer（`owns_paths` + 锁）。**可并行：** 检索、研究、独立评审、互不争夺的工件。**不可并行：** 同一文件/schema、写依赖，或协调/token 税超过加速 — 退回单会话。真正并行写之前必须 worktree 隔离。 |
| I5 | **门禁失败关闭** | 测试失败、校验失败或评分失败 → 阻断推进。门禁失败时永不标为 `DONE`。 |
| I6 | **人类架构、人闸与理解** | 人类定规格、权衡、预算与品味。可外包起草/思考辅助 — **不可**外包系统理解或发布责任。高风险动作需要明确人审。加速是 **agentic 工程**（守住质量门槛），不是把漏洞 vibe 上线的编码。 |
| I7 | **诚实标注自主度** | 若某步是脚本/编排，在代码注释与 handoff 中如实说明。写明 **A\*** 档位（§6）。不假装 LLM 自主，不假装 git commit。 |
| I8 | **先窄成功定义** | 先交付一条薄垂直切片（如条款门禁 SC-01..03 + 审计策略），再加角色、并行或领域。优先带**廉价客观验证**的切片。 |

## 3. 角色模型（中继队，非蜂群）

保持阵容 **小而锋利**（约 3 个核心角色 + 可选只读工具）。宁可 7 个清晰技能，也不要 100 个含糊技能。

### 3.1 核心角色（必需）

| 角色 | 工厂名 | Sabrina 类比 | 拥有 | 不得 |
|------|--------|--------------|------|------|
| Planner | Orchestrator | Content coach | 澄清目标；检索政策/品牌；产出 **验收契约** + 特性/里程碑列表；根据 validator 报告打开 **fix** 特性 | 实现产品代码；最终验收 |
| Builder | Worker | Post writer | 每特性新鲜上下文；先测后码；真实补丁 + 真实 VCS handoff；遵守 `owns_paths` | 最终合规/评分验收；在另一 writer 运行时持有写锁 |
| Judge | Validator | Post grader | 独立检索配置/模型；对照 **契约** 细审 + 黑盒检查；只发失败报告；追求 **与人类校准** 的判断 | 修补被测系统；「好心」削弱契约 |

### 3.2 可选专家（只读或互不冲突）

- **Hook/Pattern 库** / 政策条款查找 — 工具 Agent，不是同一批文件上的第二写者  
- **改写 / 扇出** — 仅当输出**不**争夺同一可变工件。**绝不**在无锁/worktree 时把多个 writer 扇进同一 git 分支。  
- **调度 / 发布 / 部署** — 执行 Agent，**必须在人审门禁之后**

### 3.3 软编排，硬账本（掌控循环）

- 行为策略（拆分 / 重试 / 升级）：提示词 / 技能（软）。  
- 控制流、工具执行、重试、暂停/恢复、审批：**确定性应用代码**（硬）。LLM 发出结构化意图；应用拥有 switch。  
- 软层可随更强模型改进；硬层不得依赖模型记忆。  
- 优先 **脑 ≠ 手**：规划/账本/harness 放在沙箱文件/shell 变更的爆炸半径之外。

## 4. 共享工件（记忆总线）

所有 Agent 通过版本化工件读写。上下文窗口可弃，并**刻意压缩**。

| 工件 | 内容 | 生产者 | 消费者 |
|------|------|--------|--------|
| **验收契约** | 行为断言、验收、`machine_check`、`policy_clause_id`、广播约束 | Orchestrator | Worker、Validator、人类 |
| **品牌 / 领域 brief** | 语气、产品、受众、非目标 — 本仓库：claims KB 中的 **政策 + 产品约束**（`CONTEXT.md` glossary） | 人类 + Orchestrator | 所有角色 |
| **特性列表** | 里程碑、claims 断言、`owns_paths`、kind=`implement`\|`fix` | Orchestrator | Runner、Worker |
| **RAG 知识库** | 政策、API 文档、审计发现、runbook；**版本 + 生效日**；通过后的回写 | 人类 + 细审更新 | 所有角色（按角色检索配置） |
| **Handoff 记录** | 已做 / 未做、命令 + 退出码、引用、process_followed、blocked_for_human — 为下一步 **压缩** | 每一角色 | Runner、Mission Control、下一 Agent、人类 |
| **评分 / 校验报告** | 通过/失败（或分数）、备注、引用；可选人类抽检字段 | Validator/Grader | Orchestrator（开 fix）、人类 |
| **Mission Control 状态** | 阶段、角色、写锁、预算、事件日志、审批人闸 | Runner | 人类（异步监督） |

### 4.1 契约质量规则

- 断言描述**可观察行为**，不描述实现。  
- 每条断言引用 KB 条款 ID；引用含 `doc_id`、`chunk_id`、`doc_version`、`retrieved_by`、`retrieval_profile`。  
- Validator 用契约 + **独立**检索评判 — 不以 Worker 笔记为唯一证据。  
- 优先**执行** `machine_check`（API/E2E/脚本），而非硬编码 `A-001` 开关。  
- 先在验证廉价且客观处自动化（**可验证性经济**）；低可验证判断留给人类。

### 4.2 评分门禁（可校准法官）

- 显式阈值（全部断言通过；或分数 ≥ 9/10）。  
- 循环：构建 → 评判 → 修复 → 评判，直到达标或 **预算耗尽 → 人类**。  
- 限制修订轮次（如 3–5）。正确性预算优于虚荣吞吐。  
- 长期：抽检法官与人类一致性；独立但未校准的法官仍可能系统犯错。

### 4.3 上下文加载策略（能否扩展？）

每一项定制都在与可用于干活的 token 竞争。新增技能、MCP 或 always-on brief 段之前，问 **能否扩展到** monorepo / 多仓机构规模。省 token **不**放松 I5：验收仍须执行门禁 — **verify-then-DONE**。

| 机制 | 加载成本 | 优先场景 |
|------|----------|----------|
| Always-on brief / 巨型项目圣经 | 最高（每轮都付） | 仅硬约束 + 地图 + 指针（保持极小）— 见 §0 |
| MCP 工具 schema | 多工具常驻时高 | 多客户端 / IDE 可移植，或无稳定 CLI；工具数保持小或可搜索 |
| 技能（短描述常驻；正文按需） | 中 | 可重复工作流；描述写到能精确触发 |
| 子 Agent（独立窗口 → 压缩摘要） | 描述中等；正文隔离更好 | 大只读研究/评审，不得污染写者上下文 |
| 事件 hooks / 脚本（匹配时才注入） | 常驻税最低 | lint、typecheck、契约检查、犯错时政策轻推 |

规则：

- 「红波浪」反馈优先用 **hooks / 确定性脚本**（犯错时），不要只靠延后的全量编译发现。Hooks 是 **硬循环信号**：在确定性应用/harness 中运行，向受控循环注入结构化结果 — **不是**在 §3.3 之外重规划的第二软脑。  
- **内部公司 harness：** 优先 **CLI + 技能「何时/如何用」**，而非增生 MCP。**例外：** 面向可移植 IDE / 多客户端插件时，MCP（或等价物）是合法可移植层 — 仍须精简 schema；工具膨胀一样稀释选择。  
- **不要**为追相关性而在会话中途 LRU 换掉大块规则，若这会打爆前缀缓存并倍增成本 — 应改为稳定前缀 + 懒正文。  
- 技能/MCP **描述不是免费的**；成千上万含糊描述会重造 always-on 税。限制数量；描述要决策就绪。

## 5. 控制流（规范循环）

```text
人类目标 / 政策变更
    → Orchestrator：RAG → 验收契约 + 特性（+ 广播约束）
    → for feature in 串行队列:
          获取写锁
          Worker：窄 RAG → 测试 → 实现 → 真实 commit → handoff
          释放写锁
    → Validator：独立 RAG + 细审 + 对照契约黑盒
    → 若失败：Orchestrator 打开 fix 特性（Worker 不得自合并绕过）
    → 若通过：提议版本化 KB/技能回写 → 具名评审人晋升（默认人闸；Validator 仅可提议/打分）
    → 若高风险副作用：HUMAN APPROVE → Scheduler/Deployer
    → 若阻塞：停给人（禁止静默无限重试）
```

**并行决策树（I4）：**  
研究/检索/评审 → 可并行 →  
同一可变工件或写依赖 → 串行 / 单一所有者 →  
协调或 token 税 > 加速 → 单会话。

## 6. 自主度阶梯（A\* — 不得跳档）

**命名：** 用 **A0–A5** 表示 *Agent/harness 自主度*。**不要**把这些字母复用于产品集成层级。

| 产品 / 领域术语（条款门禁） | 含义 | 不等于 |
|-----------------------------|------|--------|
| **Integration L1** | 只读案件头字段 | A1 |
| **Integration L2** | 核心回写模拟（如出款就绪状态） | A2 |
| **Integration L3** | 自动出款 / 银企 — **本仓库 Won't** | A3 |

实现本系统的 Agent **必须**诚实优先地爬档：

| 档位 | 名称 | 允许行为 | 本仓库目标 |
|------|------|----------|------------|
| **A0** | **编排（Choreography）** | 确定性脚本；固定契约；开关切换 | 历史演示基线 — 须明确标注 |
| **A1** | **门禁骨架** | 真实测试失败关闭；真实 HTTP 黑盒 validator；无假 git；禁止未使用的 `goal` | **继续改动的最低门槛**（轨 A `machine_check`） |
| **A2** | **Schema 约束 Agent** | LLM 输出经 JSON Schema 校验；契约/特性解析而非信任原文 | 下一步（mission control 路径） |
| **A3** | **可打补丁的 Worker** | Worker 编辑 worktree；handoff 含真实 diff + commit hash | **当前仓库目标（fix 路径）** |
| **A4** | **契约驱动法官** | 检查来自验收/`machine_check`；独立模型/提供商；通向人类校准 | 反偏差叙事所需；对齐 Issues 10–11 / Phase 2a W2 |
| **A5** | **生产人闸** | 预算、审批、工具 ACL、凭证代理、动作审计 | 面试 + 真实运维门槛；阻塞于 §14 #2 |

改代码时：**优先升一档 A，而不是加角色剧场。**  
UI / 作业壳完工（Phase 2a W0）是 **产品表面**，不自动等于升到 A3–A5。

## 7. 工具哲学（Agent 原生产品）

**Agent 需要的三面（Access / Knowledge / Tooling）：**

- **Access：** 若人类完成真实工作日离不开仓库 shell（CI 日志、runbook、内部 CLI、工单、仪表盘），Agent 在这些面可通过稳定工具到达之前，无法分担该工作 — 禁止「粘贴进提示词」凑合。先扩展 **工作面**，再怪模型。新 Access 工具必须落在 §14 #2 所述 **凭证代理、网络策略与动作允许列表** 之后 — 无网关的 Access 教义是政策剧场。在 §14 #2 落地前，新 Access 须标 **demo-only** 或 **human-gated**（含 Phase 2a W1 LangSmith）。  
- **Knowledge：** 机构惯例、失败实验、内部词汇、「上周刚变」的事实住在账本/KB/技能（I3）— 不会从训练数据里冒出来。  
- **Tooling / 反馈：** 最快的本地改进往往是 **更紧的反馈环**（编辑后 typecheck、lint、契约校验），而不是更厚的 always-on 提示。

**工具偏好序：**

1. 稳定的 **CLI / HTTP API**（机器可读鉴权、限流、文档、**stdout 契约**：退出码 + Agent 可行动的结构化错误）。  
2. 短 **技能**，教 *何时* 与 *如何* 用那些 CLI。  
3. **MCP** 当 (a) 跨 IDE/客户端可移植重要，或 (b) 无 CLI — 保持 schema 精简；工具膨胀稀释选择。对 **单一内部 harness** 且已有好 CLI，优先 1–2，勿发明 MCP 包装。  
4. 工具是由 **确定性** 代码执行的结构化意图（掌控循环）。

**随智力扩展的工具：**

- 优先 **轻推**（提醒、事件时注入的政策提示），它们在模型变强后仍有用。  
- **硬阻断** 仅用于真爆炸半径（生产写、凭证外泄、共享分支并行写者）。  
- 按角色最小权限；**脑/harness** 不得与沙箱变更共享爆炸半径。  
- 高风险副作用留在人闸之后（I6），包括会倍增会话的任何「自动」模式。

**回写评审人（对齐 I3）：**

- 会话记忆 / handoff 笔记可 **提议** KB 或技能更新。  
- **晋升** 进入版本化机构技能/KB 需要显式评审人：默认 **人闸**；Validator 可对照契约质量打分或拒绝候选，但 **不得** 静默合并回写。Worker 永不自晋升。

**运维：**

- 支持暂停/恢复与「联系人类」作为一等工具结果。  
- Mission Control 监督里程碑与门禁 — 不是原始 token 流。只读并行或 worktree 隔离会话增多时，为 **人类注意力** 优化（标注会话、压缩状态），绝不靠削弱 I4/I5「修复」。

## 8. 模型分工（「Droid whispering」）

- Orchestrator：最强推理 / 规划。  
- Worker：强编码、成本敏感。  
- Validator：指令严格、怀疑倾向；**优先不同提供商或检索配置**。  
- 架构保持模型无关；换模型无需重写账本。

## 9. 本仓库领域默认

**条款门禁（Claims Gate）** 为默认垂直（见根目录 `CONTEXT.md` 与 `PRD_02_INSURANCE_CLAIMS_GATE.md`）：

- 共享 brief ≡ 政策 + 条款 KB + API + 审计发现约束（效力栈、citation 三联门）。  
- Grader ≡ 对照版本化条款 / `policy_clause_id` 的合规 Validator — 主接缝 **`machine_check` HTTP 黑盒**。  
- 发布人闸 ≡ **人闸令牌** 之后才可 `PAYOUT_READY` / 对外通知；演示用审批标志 / 令牌 — **无 Integration L3 自动出款**。  
- 推理诚实 ≡ 确定性轨 A 默认；可选 LLM 辅助（轨 B）不得进入默认绿 CI。

内容运营 / 转账演示隐喻只可启发 **评分表形状**。除非人类改垂直，否则不要把 `POL-XFER-*` 重新设为产品默认。

## 10. 反模式（评审拒绝）

1. 一个长跑 Agent 既规划、编码又自验收。  
2. 测试/校验失败仍标特性 `DONE`。  
3. 假 commit、假「遵守 owns_paths」、未使用的 `goal` 参数。  
4. 「为了速度」在同一分支上并行写者。  
5. 把整份 KB / 原始日志塞进上下文，而非排序引用 + 压缩 handoff。  
6. Validator「就这一次」改代码。  
7. 无限修订环，无预算或无人升级。  
8. 仍停在自主度 **A0** 却宣称生产级多 Agent。  
9. 膨胀到几十个重叠 Agent/技能。  
10. 优化发帖量 / PR 数优先于契约通过率。  
11. 仅私有窗口的 Agent 胜利，从不回写 KB/技能。  
12. 为「更快」交付 vibe 出的安全/正确性回退。  
13. Always-on 巨型 brief / 无条件插件式上下文倾倒，开工前烧光窗口（包括粘贴本文件全文）。  
14. 为「完整」增生 MCP 或技能描述，使工具/技能选择稀释、常驻税主导 — 且无 hooks 或懒正文。  
15. 把 Phase 2a 作业壳 / LangSmith UI 完工当成 **A5** 生产人闸的证据。

## 12. 成功指标（已接线 — 「好」的含义）

主指标必须 **可观测**，不能只是口号。某行接线未存在前，视为 **aspirational**，不得宣称运维成熟。

| 指标 | 类别 | 接线（本仓库） | 状态 |
|------|------|----------------|------|
| 里程碑校验后契约断言通过率 | Primary | `pytest -q` 轨 A + SPEC `machine_check` / SC-01..03 | **已接线** |
| Fix 特性比与校验轮次 | Primary | Issue Answer / handoff 修订计数；期望 >1 | 手工 / 工单 |
| 逃逸缺陷（Validator 抓住、Worker 测试漏） | Primary | Validator 失败报告 vs Worker 测试日志 | 手工直至 Mission Control 事件 |
| 引用覆盖（有效条款版本的断言占比） | Primary | Citation 三联门测试；KB 版本字段 | **已接线**（轨 A） |
| 验证成本 vs 墙钟 | Primary | CI 时长 + 可选 LangSmith/本地 trace | 部分（W0 本地 trace；W1 LangSmith） |
| 每里程碑人类工时 | Secondary | 操作者日志 / 未自动化 | Aspirational |
| 门禁耗时；审批队列新鲜度 | Secondary | API / SQLite ledger 中人闸事件时间戳 | 部分（W0+） |
| 回写率（通过 → KB/技能） | Secondary | 经审晋升的 PR / 技能 diff | 薄（§14 #7） |
| 法官–人类一致率（κ / 抽检） | Secondary | Issues 10–11 字段；Phase 2a **W2** OpenEval | 波次绑定 |
| 并发下注意力 | Secondary | Mission Control 多会话 UX | Deferred（§14 #10） |
| Hook / 轻推假阳性率 | Secondary | Hook 负责人仪表 / 调优日志 | Aspirational |

Secondary 永不压过 Primary。不得靠跳过锁或失败关闭门禁来「修复」注意力。

## 13. 可供 Agent 引用的摘要

> 建 **中继**，不建蜂巢。  
> **契约先于代码；只自动化你能验证的。**  
> **一个写者；多个读者；仅在便宜时并行。**  
> **持久账本；精选上下文；经回写复利。**  
> **独立、可校准的法官；人闸与理解。**  
> **掌控循环；爬 A 阶梯；正确性复利。**  
> **刻意征收上下文税；优先 hooks 与懒技能。**  
> **扩展工作面，而不是倾倒。**  
> **A\* ≠ Integration L\*；作业壳 ≠ 生产人闸。**
