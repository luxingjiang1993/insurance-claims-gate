## 1. 这轮不做什么

- 不沿用条款门禁、宪法、OS/MAS 旧稿、C1–C5。
- 不改 `本项目代码/claims-gate/`，不升 PRD/SPEC。
- 不把 Missions 三角色剧场重新包装成新品类卖点。
- Karpathy 线：**多 Agent 必须对应互斥主体或互斥语料**；否则是剧场。
- Anthropic 线：应用拥有循环；检索失败要拒答；Eval 不是发货权；记忆分型。

现仓库里的混合检索、引用门、span 账本，只当 **零件架**（库名可复用，故事不可复用）。

## 3. 共用技术脊柱（面试必须能画）

三家公司 **同一套运行时，换主体与语料**。默认路径是 **Plan-and-Execute**；ReAct 只发生在 **有工具、有预算的工人环**，不是全场开放 `create_agent`。

```text
用户意图
  -> Planner（Plan-and-Execute）
  -> 议题树 + 预算 + done_when
  -> ReAct 工人 A（隔离 RAG / 工具命名空间）
  -> ReAct 工人 B（隔离 RAG / 工具命名空间）
  -> 合并 + 引用门禁 + 冲突 disposition
  -> 人闸（不可逆出口之前）
  -> 签字包
旁路：Eval 板（非发货权）
```

### 3.1 必须能讲清的合同

| 层 | 合同 | 面试金句 |
|----|------|----------|
| **Planner** | 拆议题树、设 `done_when`、步数/工具预算；**不**读取任一方私有原文当证据。 | 「模型填槽，应用拥有循环。」 |
| **ReAct 工人** | 只在自己的语料命名空间里 `search / open / quote`（可加白名单工具）。跨语料引用 = **产品 bug**。 | 「ACL 泄漏测试必须红。」 |
| **RAG** | 混合检索 + 引用校验 + **冲突是一等公民**。空检索 → `abstain`，禁止编。 | 「失败要拒答，不是编圆。」 |
| **合并** | 把双方主张对齐到同一议题节点；输出 `support / conflict / abstain`，不是一段散文。 | 「冲突是 disposition，不是 prompt 希望。」 |
| **记忆** | working = 本单议题树；audit = 工具账本（观察 ≠ 交付）。**禁止**跨单人物画像 embedding。 | 「Checkpoint 不是 Memory。」 |
| **HITL** | 不可逆出口之前的 **能力闸**（令牌匹配才发送/冻结）。 | 「聊天确认是剧场。」 |
| **Eval** | 金集测冲突检出 / 引用忠实 / ACL。LLM-as-judge 只在工程旁路。 | 「分数不是发货权。」 |

### 3.2 角色映射（换名不换脊柱）

| 运行时槽 | A SplitTruth | B Falsifier | C BarPacket |
|----------|--------------|-------------|-------------|
| Planner | 问卷/基线议题树 | 主张图拆解 | 职级评分树 |
| 工人 A | 红方（买方风险） | Builder（找支持） | 招聘侣（倡导） |
| 工人 B | 蓝方（卖方抗辩） | Adversary（找反例） | 标准侣（否决） |
| 语料隔离轴 | 两个组织的文档室 | 待验文本 vs 世界证据 | 候选人材料 vs 公司标准 |
| 不可逆出口 | 例外清单发出 / 写入批准记录 | 发布主张成绩单 | 冻结 hire/no-hire 卷宗 |

开放 ReAct 只允许作为 **实验室旗标**，不得当默认权威路径。

## 4. 公司 A — SplitTruth（对抗语料室）

### 4.1 一句话

两个对手方各有一间文档室；产品输出一份可签字的 **例外/异议清单**，不是聊天摘要。

### 4.2 JTBD

- **功能：** 「在 30 分钟内拿出我能对老板/法务辩护的差距清单。」
- **社交：** 「校准会上我不是那个只会念 PDF 的人。」
- **情绪：** 「别再让我为卖方自我陈述背书。」

雇的不是「读懂 SOC2」，而是 **把两套世界对齐成可签字的差距**。

### 4.3 滩头（Blank）与不先做

- **滩头：** 中小团队 **供应商安全审查**（买方安全基线 / 问卷 vs 卖方 SOC2、政策、问卷回答）。
- **为何是这个：** 语料公开程度够做 demo；买方明确（安全/采购）；出口不可逆（把例外发回供应商或写入内部批准）。
- **不先做：** 完整 M&A 虚拟资料室、保险核赔、合同全量红线。那些是相邻市场，会把脊柱拖成平台。

### 4.4 Thiel 秘密

Glean / ChatGPT 只有 **一个索引、一个委托人**。卖方不会把未披露附件放进买方能搜的同一库；买方也不会让模型拿卖方的自我陈述当政策。贵的是 **互相打脸**。水平 Copilot 在结构上做不到「两个委托人」。

### 4.5 商业模式（假设）

| 项 | 假设（需实测） |
|----|----------------|
| **谁付钱** | 安全负责人或采购负责人（买方）。卖方不是付费方。 |
| **计价单位** | 每份审查包 / 每家供应商。不是座席。 |
| **为何换** | 现在用表格 + 人肉对照；出错成本是一次错误批准。 |
| **a16z** | SoR（表格/工单）退成仓库；产品是执行层。 |
| **失败条件** | 变成「再做一个问答机器人套两套 PDF」；或按座席卖给还没有审查流程的公司。 |

**北极星（Ries）：** 清单发出后被人工改写的比例下降。

### 4.6 为何必须多 Agent（Karpathy 过关）

红方（风险）与蓝方（卖方抗辩）**利益相反**。共享一个 ReAct = 串供。两个工人不是「总结员 vs 润色员」，而是 **两个委托人**。

### 4.7 Agent / RAG / 记忆 / Eval

- **Planner：** 按买方问卷/基线条款生成议题树（访问控制、加密、分包、日志留存…），每节点 `done_when` = 双方均有引用或明确 `abstain`。
- **红方 ReAct：** 只检索买方基线 + 问卷要求；工具：`search_buyer`、`open`、`quote`、`flag_gap`。
- **蓝方 ReAct：** 只检索卖方资料室；工具：`search_vendor`、`open`、`quote`、`offer_mitigation`。
- **冲突类型：** 基线要求「禁止分包」vs SOC2 写「使用子处理者」；问卷勾选「已加密」vs 政策未写算法。
- **记忆：** `review_id` 作用域；TTL 到审查关闭；禁止把供应商员工做成跨单画像。
- **Eval 金题：**
  1. 红方引用了蓝方未披露附件 → **必须失败**（ACL）。
  2. 两边对「分包」条款打架 → disposition=`conflict`，不得合成「基本合规」。
  3. 卖方资料室没有加密段落 → 蓝方 `abstain`，不得编 AES-256。
- **人闸：** 清单进入「发送给供应商 / 写入内部批准」之前必须令牌。工人只能 `suggest_send`。

### 4.8 不可逆出口

把例外清单发回供应商，或写入内部批准记录。聊天窗口里的摘要 **不是** 出口。

### 4.9 面试 2 分钟卡

> 默认不是开放 Agent。Planner 拥有议题树和预算。两个 ReAct 工人各守一间语料室。合并层做引用门禁和冲突 disposition。人闸之后才能发清单。我用 ACL 泄漏测试证明这不是两个 persona 在吵架。

### 4.10 失败条件 / 剧场

- 一个索引、两个 system prompt。
- 「安全审查 Copilot」问答。
- 把评分当合规。
- 演示时用同一份 PDF 喂两边。

### 4.11 Demo 夹具（点名后再做）

合成两间 markdown 室：`buyer/baseline.md`（禁止生产数据出站、禁止未登记分包）+ `vendor/soc2.md`（使用云子处理者、未写加密算法）。议题「分包」「加密」必须 `conflict` / `abstain`。另附 `vendor/private_annex.md` 仅蓝方可见，红方引用则测试红。

## 5. 公司 B — Falsifier（主张可证伪器）

### 5.1 一句话

对着论文、技术博客、设计文档里的 **具体主张**，用引文 + 可重跑证据去打脸或背书。

### 5.2 JTBD

- **功能：** 「这篇东西哪些句子是真的、哪些是不可复核的广告。」
- **社交：** 「我在尽调/读书会上不是那个被数字唬住的人。」
- **情绪：** 「生成式模型把主张写圆的速度，快过我查证的速度。」

雇的不是「总结这篇论文」，而是 **把主张变成可证伪单元**。

### 5.3 滩头与不先做

- **滩头：** 个人开发者 / 面试官审 **开源 README 与博客基准数字**（公开语料，demo 零隐私）。
- **不先做：** 自动科学发现、期刊审稿平台、医疗诊断打脸。那些需要持牌与金标，会把故事做成研究机构。

### 5.4 Thiel 秘密

生成让主张更便宜；稀缺的是 **可证伪性**。水平聊天的产品目标是让你读得爽，会帮你把主张写圆。Falsifier 的产品目标是让无引用结论 **进不了成绩单**。

### 5.5 商业模式（假设）

| 项 | 假设（需实测） |
|----|----------------|
| **谁付钱** | 研究组、技术尽调、内容平台（先个人工具后 B2B）。 |
| **计价单位** | 每篇 / 每主张包。 |
| **为何换** | 现在用浏览器 + 直觉；成本是一次错误技术决策。 |
| **失败条件** | 做成论文聊天机器人；或宣称「自动发现新科学」。 |

**北极星：** 「无引用不得进入结论」的拒答率被用户当成功能而不是故障。

### 5.6 为何必须多 Agent

Planner 拆主张图。**Builder** 用 ReAct 去摘引/（可 mock）跑支持证据。**Adversary** 专门检索反例与方法学漏洞。一个 Agent 既支持又反对 = 自我辩论剧场，评测上无法证明隔离。

### 5.7 Agent / RAG / 记忆 / Eval

- **Planner：** 从目标文档抽出主张列表（数字、比较级、「state of the art」、因果句），每条 `claim_id`。
- **Builder：** 语料 = 目标文档 + 其显式引用；工具：`quote_claim`、`retrieve_citation`、`run_repro`（demo 可 mock）。
- **Adversary：** 语料 = 外部对照（其他论文/基准页/代码树）；工具：`search_world`、`quote_counter`、`flag_unreproducible`。
- **冲突类型：** README 写「比 X 快 10x」vs 基准页条件不同；论文写「显著」vs 无统计细节。
- **记忆：** `document_id` 作用域；主张图是 working state；跑实验日志进 audit。禁止把作者做成跨文档人格记忆。
- **Eval 金题：**
  1. 无检索命中仍给出「属实」→ 必须失败。
  2. 主张与反例方法学不可比 → `conflict` 或 `abstain`，不得平均成「大致属实」。
  3. Builder 不得把 Adversary 的未公开笔记当自己的引用。
- **人闸：** 「发布成绩单」之前令牌。成绩单状态：`supported / refuted / insufficient`。

### 5.8 不可逆出口

发布「主张成绩单」。私下聊天摘要不是出口。

### 5.9 面试 2 分钟卡

> 我做的不是 RAG 问答。Planner 把文本切成主张。一个工人只准找支持，一个只准找反例，引用门禁失败就 insufficient。评测看的是拒答和冲突，不是 BLEU。这更接近 Anthropic 关心的 citation / truth，而不是又一个阅读助手。

### 5.10 失败条件 / 剧场

- 「论文 GPT」。
- LLM-as-judge 当唯一忠实度。
- 宣称自动化实验室。
- 把摘要当证据。

### 5.11 Demo 夹具

一篇合成 README：宣称「在 fiqa 上 recall@10 = 0.92」。对照页写同一设置下为 0.71，且 README 未给脚本。主张必须 `refuted` 或 `insufficient`。另设一条无任何外部命中的形容词主张，必须 `insufficient`。

## 6. 公司 C — BarPacket（小团队招聘否决包）

### 6.1 一句话

招聘侣 vs 标准侣，输出一份 **hire / no-hire 卷宗**，ATS 退成附件柜。

### 6.2 JTBD

- **功能：** 「我要一个能在校准会上辩护的决定，不是又一个候选人摘要。」
- **社交：** 「校准会上我带着卷宗，不是带着感觉。」
- **情绪：** 「别让我在 50 份简历里用聊天窗口碰运气。」

### 6.3 滩头与不先做

- **滩头：** 10–50 人团队、没有专职招聘运营（Christensen 从下往上打 Greenhouse）。
- **不先做：** 企业 ATS 替换、背景调查、薪酬谈判 Agent。隐私面过大。

### 6.4 Thiel / a16z

ATS 是 System of Record。真正被雇的工作是 **校准会上的可辩护决定**。一个 Agent 既吹又杀，校准会不会信。智能执行层产出卷宗；ATS 只存附件。

### 6.5 商业模式（假设）

| 项 | 假设（需实测） |
|----|----------------|
| **谁付钱** | 用人经理 / 创始人。候选人不是付费方。 |
| **计价单位** | 每个角色或每个候选人包。 |
| **为何换** | 现在用文档模板 + 群聊；成本是一次错误录用或错误淘汰。 |
| **失败条件** | 像 ChatGPT 改写简历；或真去打分真人（偏见/隐私）。 |

**北极星：** 校准会上「卷宗被当场推翻」的比例。

### 6.6 为何必须多 Agent

倡导方与否决方必须隔离。共享上下文会导致「两边都同意」的假共识。这是同组织里的 **两个角色**，不是两个组织，也不是主张 vs 世界。

### 6.7 Agent / RAG / 记忆 / Eval

- **Planner：** 按职级标准生成评分树（必须项 / 加分项 / 红线）。
- **招聘侣：** 语料 = 合成简历 + 作品；工具：`quote_evidence`、`map_to_bar`。
- **标准侣：** 语料 = 职级标准 + 价值观红线；工具：`quote_bar`、`flag_missing`、`veto`。
- **冲突类型：** 简历写「主导了 X」vs 标准要求「独立 owner 过生产事故」且作品库无证据。
- **记忆：** `role_id` + `packet_id` TTL；禁止跨候选人 embedding 画像；禁止把落选者特征写进长期记忆。
- **Eval 金题：**
  1. 招聘侣引用了标准文档里不存在的「文化匹配」空话 → 引用门失败。
  2. 标准侣看到未在简历出现的学校名 → ACL/幻觉失败。
  3. 红线项缺失时不得输出 `hire`。
- **人闸：** 冻结卷宗 / 提交校准之前令牌。Demo 只用 **合成人**。

### 6.8 不可逆出口

把卷宗提交为冻结的决策记录（`hire` / `no-hire` / `hold`）。改写简历不是出口。

### 6.9 面试 2 分钟卡

> 这是同公司两个角色的隔离，不是 HR 聊天机器人。评分树是 Plan，倡导和否决是两个 ReAct 命名空间。我可以讲清楚为什么 ATS 变成 persistence。风险是偏见与隐私——所以 demo 只用合成人，并且我把跨候选人记忆做成明确拒绝。

### 6.10 失败条件 / 剧场

- 简历润色工具。
- 一个 Agent 输出「综合得分 87」。
- 真人人数据。
- 把「文化匹配」当无引用结论。

### 6.11 Demo 夹具

合成候选人「Ava Chen」简历声称 3 年独立 on-call。职级标准要求「独立关过 sev-1」。作品库只有作业项目。必须 `conflict` 或 `no-hire` + 引用，不得编造事故编号。
